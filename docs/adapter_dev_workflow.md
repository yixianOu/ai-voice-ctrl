# 外部应用适配层开发与测试流程

## 1. 规划阶段
- 明确需要支持的应用与操作清单（例如 VLC 播放、VS Code 文件操作）。
- 为每类操作定义统一接口签名与错误约定，确认输入输出格式。
- 列出平台依赖（CLI、HTTP API、配置文件），确保开发环境已安装并可手动调用。

## 2. 基础骨架搭建
- 在 `backend` 目录下建立适配层包，定义对上层暴露的接口及数据结构。
- 先实现一个 `Mock` 版本，返回固定结果以保证整体编译通过。
- 接入 Wails Go 后端，暴露基础方法给前端，用于后续联调。

## 3. 具体适配器实现
- 针对每个目标应用编写独立的实现结构体，例如 `VLCController`、`VSCodeController`。
- 封装底层命令或 HTTP 请求，处理参数校验、超时与错误分类。
- 为跨平台差异准备扩展点：使用 build tags 或运行时配置区分 Windows / Linux。

## 4. 单元与集成测试
- 为关键方法编写单元测试，覆盖参数错误、命令失败等分支。
- 编写可选的集成测试（标记 build tag），在本地真实调用外部应用时执行。
- 提供简单 CLI 或脚本入口，方便手工验证适配器行为。

## 5. 日志与观测
- 在适配层统一记录执行日志（命令、参数、返回状态），方便后续调试与 LLM 对接。
- 预留指标或事件钩子，以便未来接入监控。

## 6. 预留 MCP 对接
- 抽象出统一的 `ExecuteCommand(name string, payload map[string]any)` 入口，便于改造成 MCP Handler。
- 保持所有公共结构可以序列化为 JSON，符合 MCP 消息体格式。

## 7. 联调与回归
- 使用 Wails 前端按钮或 API 调用触发适配层方法，确认与 UI 数据流吻合。
- 编写回归清单：新增操作、参数校验、错误提示、外部应用状态变化。
- 在 LLM 调度尚未实现的阶段，使用模拟指令（JSON 文件或 CLI 参数）验证完整流程。
